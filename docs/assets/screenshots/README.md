# Screenshot Guide

Use this folder for production-ready screenshots that make the project easy to understand in GitHub, portfolio reviews, and academic demonstrations.

## Recommended Captures

| File | Caption | Notes |
| --- | --- | --- |
| `01-login.png` | Firebase-backed login and onboarding entry point | Capture the default public entry screen. |
| `02-dashboard.png` | Learner dashboard with progress and next actions | Use seeded learner data if available. |
| `03-module-viewer.png` | Video lesson and module completion workflow | Show a loaded module video and lesson content. |
| `04-diagnostic-pretest.png` | Diagnostic assessment interface | Avoid exposing real student data. |
| `05-gap-analysis.png` | Competency gap visualization | Capture the chart and recommended next step. |
| `06-personalized-study-plan.png` | AI-assisted reviewer generation | Use non-sensitive sample assessment data. |
| `07-review-modes.png` | Flashcards, audiobook, and cheatsheet review options | A collage or single review landing screen works well. |
| `08-certification.png` | Learning results and certificate output | Use a demo learner name. |
| `09-admin-dashboard.png` | Admin analytics overview | Blur or seed user names and emails. |
| `10-item-analysis.png` | Assessment item performance review | Use sample data only. |

## Capture Guidelines

- Use a desktop viewport around 1440px wide for primary screenshots.
- Use consistent browser zoom, preferably 100%.
- Do not show real credentials, emails, API keys, or student records.
- Prefer seeded or demo data for admin views.
- Keep filenames lowercase and numbered so README ordering stays stable.

## Optional Mobile Captures

If adding mobile screenshots, use the suffix `-mobile`, for example:

```txt
02-dashboard-mobile.png
05-gap-analysis-mobile.png
```
